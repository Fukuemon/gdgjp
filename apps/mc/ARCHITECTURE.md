# mc architecture

- `app/routes/controller.tsx` is the operator screen (auth + chapter); `app/routes/play.tsx` is
  the OBS player (public page, token-gated socket, renders nothing).
- `features/clips/` owns the generated catalogue (`clips.json`) and the transcript math
  (character offset at a time, marquee offset). Generated by `scripts/build-clips.mjs`.
- `features/playback/` owns the wire protocol, the reliable socket (heartbeat, endless
  reconnect), the ack tracker, confirmation rules (`intent.ts`), the player engine, and the
  controller room hook. `components/` holds the seek bar, scrolling transcript, cards, the
  floating bar, status lamps and diagnostics.
- `features/auth/` owns relying-party sessions and chapter membership (copied from roster).
- `lib/frame.ts` is the single shared requestAnimationFrame loop.
- `workers/mc-room.ts` is the only Durable Object (`getByName("main")`). It stores the player
  token, played marks, loop settings and the event log in synchronous KV; per-socket state lives
  in hibernation attachments.

Reliability rules:

- Commands are never queued. With no player, the room fails them immediately.
- A play only acks once the player's media clock has advanced.
- The player is the source of truth for playback state; it reports every 250 ms while audible
  and every second otherwise, which doubles as its liveness signal.
- Both sides ping every second via the DO auto-response; 3 s without a pong forces a reconnect.
